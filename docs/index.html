M.A.S.O.N.

A voice sidekick for Batocera. Ask about the game you're playing, translate a screen, and get a spoken answer — without leaving the couch.

Project MASON is Matt's idea — a Batocera sidekick named after his son Mason.

Setup

You need: a Batocera box, internet, and a free Groq API key (console.groq.com). No packages to install, no manual steps — one command does the whole thing.

1. Run the installer on the Batocera box

Over SSH, or on the box itself with the F1 terminal. Paste this:

curl -fsSL -o /tmp/mason-install.sh https://raw.githubusercontent.com/NOOBMASTER2099/batocera-grok/mason-v2/mason-install.sh && sh /tmp/mason-install.sh

The installer asks you exactly one thing: your Groq API key (hidden input). It's stored on your box only, locked down (chmod 600), and never printed. If you skip it, you can set it later from the MASON menu.

2. Refresh the game list

START → GAME SETTINGS → REFRESH GAMELISTS

3. Launch it

Open Ports → MASON. That's it. Re-run the installer anytime to update.

Uninstall: 
sh /tmp/mason-install.sh --uninstall

(Download the installer first with the curl command above, then run it with --uninstall.)

How it works

Chat

Ports → MASON → Chat with MASON. Type a question, get an answer in text and (if voice is on) spoken out loud. /voice on / /voice off inside chat, /quit to leave.

Help with the current game

Batocera tells MASON what you launched through a real game-start hook, so it knows the game and system before you ask. From the menu, or in-game with LCTRL + 1, it answers with that context.

Look at the screen (vision)

MASON screenshots the screen and sends it to a vision model, then explains or translates what it sees. Translation is the killer feature — retro gaming is full of untranslated games, and this reads them for you.

Voice

Answers are spoken with Groq's Orpheus voice (default voice hannah, changeable in Settings). If no audio player is found on the box, you still get the text answer.

Honest limit — no on-screen bubbles during games. Batocera games run without an X window to draw on, so MASON answers out loud instead of popping text over your game. Voice hotkeys work while a game has focus; on-screen overlays don't, and any version that promises them is lying to you.

What MASON sends where

Your questions — and screenshots, when you ask a vision question — go to the Groq API, because that's where the models live. Your API key never leaves your box except to authenticate those calls. Chat history stays local in the mason folder.

Hotkeys (in-game, voice daemon running)

KeysDoes
LCTRL + 1Help with the current game, spoken
LCTRL + 2Translate the screen to English, spoken

The daemon starts automatically as a Batocera user service. You can also start/stop it from the MASON menu (options 5 and 6). The daemon is the one experimental part — see the update notes.

Troubleshooting

MASON prints real errors instead of hiding them. Here's what they mean:

You seeIt means / fix
"No Groq API key set"Ports → MASON → Settings → option 1, paste your key.
"Groq HTTP 401"Bad or expired key. Re-paste it in Settings.
"Groq HTTP 400 ... model decommissioned"A model ID retired. Check the update notes for the current ones, or re-run the installer.
Daemon "FAILED TO START"Check daemon.log. Common cause: no keyboard event device found (the daemon needs a real keyboard, not just a controller).
"no screenshot available"Your box has neither scrot nor batocera-screenshot working. Vision falls back to text-only.
"no audio player found"No aplay/paplay/ffplay/mpv on the box. Text answers still work.
MASON not in PortsRefresh the gamelist (START → GAME SETTINGS → REFRESH GAMELISTS) and check the installer finished without a FAILED line.
"no /userdata found"You ran the installer on a PC, not the Batocera box. Run it there.

Update notes

v2.0 — 2026-11-04 — full rewrite

  • Rebuilt for Batocera as it actually is: stdlib-only Python, no pacman, no pip, no pygame, no tkinter, no PIL.
  • One-shot installer with loud failures and a self-check — no more fake DONE bars over dead steps.
  • Game detection actually installed where Batocera calls it (system/scripts).
  • Hotkeys read the keyboard at the evdev level, so they work while a game has focus.
  • Daemon runs as a proper Batocera user service (v38+).
  • Current Groq models: chat openai/gpt-oss-20b, vision qwen/qwen3.8-27b, TTS canopylabs/orpheus-v1-english (hannah).
  • Errors print the real message instead of "Error contacting Groq."
  • Voice hotkey daemon + in-game screenshots: experimental, untested on real hardware. Chat, game detection, and the installer are the solid core.

v1.6 — retired, did not work

  • Ran pacman on Batocera (Buildroot — pacman doesn't exist), so nothing it tried to install ever installed.
  • Hid every install error in /dev/null while printing DONE.
  • Hotkeys used a pygame window that never has focus during a game.
  • Pointed at the retired llama-3.2-11b-vision-preview model.
  • Game-start hook was written to a folder Batocera never calls.
